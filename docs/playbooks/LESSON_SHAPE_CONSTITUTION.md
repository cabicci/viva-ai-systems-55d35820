# Lesson Shape Constitution

## Purpose

This document defines the standard lesson experience for Viva AI Systems before content review and visual implementation.

A lesson should feel clear, calm, practical, and confidence-building.

It should not feel like a textbook, a lecture, or a technical manual.

## Core principle

One lesson = one main Aha.

Every lesson must help the learner understand one main idea and apply it in one small way.

If a lesson has more than one big Aha, it should be split or simplified.

## Default lesson flow

### 1. Hero / Orientation

**Purpose:** Tell the learner what this lesson is about and why it matters now.

Must answer:

- What will I understand?
- Why should I care?
- What will I be able to do after this?

Avoid:

- Big abstract promises
- Technical terms before context
- Long introductions

### 2. Tension / Problem

**Purpose:** Show the real-life confusion or pain that makes the lesson useful.

This should make the learner feel: "آه، دي فعلًا مشكلة بتحصل."

Examples:

- "بتفتح AI ومش عارف تسأله إزاي"
- "حاسس إن الداتا كتير ومش عارف تبدأ منين"
- "بتنشر محتوى بس مش عارف إيه اللي جاب نتيجة"

### 3. Core explanation

**Purpose:** Explain the lesson's main idea in simple language.

Rules:

- One main idea
- Short paragraphs
- No hidden prerequisites
- English terms explained on first use
- Use Egyptian Arabic naturally

### 4. Example / Before-after

**Purpose:** Make the idea concrete.

A good example should show:

- Bad/common way
- Better way
- Why the better way works

Examples should feel familiar to Arabic-speaking beginners.

### 5. Glossary / Term support

**Purpose:** Explain necessary English terms without turning the lesson into a dictionary.

Use only when needed.

Rules:

- Explain first use immediately
- Keep explanation short
- Do not overload the learner with many terms at once

### 6. Visual / Diagram / Template

**Purpose:** Help the learner see the structure of the idea.

Use when it reduces confusion.

Avoid:

- Decorative diagrams
- Dense charts
- Diagrams that introduce new ideas not explained in text

### 7. Video

**Purpose:** Support the lesson's Aha, not replace the lesson.

**Placement:** After orientation and before/after core explanation.

Rules:

- Lesson must still work if video is skipped
- Video should reinforce one idea
- Do not hide mission instructions inside video only

### 8. Quick Check / Light reflection

**Purpose:** Let the learner confirm they understood the idea before the mission.

Can be:

- One question
- One choice
- One reflection
- One short comparison

This should not feel like an exam.

### 9. Mission

**Purpose:** Let the learner apply the lesson in one small action.

Follow:

- `docs/playbooks/MISSION_CONSTITUTION.md`
- `docs/playbooks/MISSION_TARGET_DESIGN.md`

Mission appears only after the learner has enough context to try.

### 10. Confidence close

**Purpose:** End with momentum.

The learner should leave knowing:

- What they just learned
- What they can now do
- What comes next

Avoid:

- Ending with pressure
- Ending with technical warnings
- Ending with a huge new concept

## Lesson density rules

- Prefer short paragraphs.
- Avoid long blocks of text.
- Avoid stacking multiple heavy blocks in a row.
- One screen should not introduce multiple new ideas.
- Mobile readability is mandatory.

## Emotional pacing

A lesson should move like this:

1. Curiosity
2. Recognition
3. Understanding
4. Small action
5. Confidence

Avoid:

- Fear-first tone
- Shame
- Overpromising
- "You should already know this" energy

## When a lesson may differ

A lesson may differ from the default flow only if there is a clear reason.

Examples:

- Intro lessons may be lighter.
- Technical Builder lessons may need extra warning or optional framing.
- End-of-module lessons may include a bigger recap or Capstone.

But the lesson must still protect:

- Beginner clarity
- One Aha
- Mobile readability
- Mission winnability

## Current content review implication

Before rewriting content, each lesson should be reviewed for:

- One Aha
- Correct flow order
- Mission fit
- English term handling
- Cognitive load
- Emotional pacing
- Mobile readability
- Ending confidence
