# Technical motion replacement — owner authorized 11 October 2026

Scope: 80 technical lessons, four locale identities (320 videos). Academic, AI,
Kids, PR165, billing and application publication are excluded. Egyptian narration
uses the accepted Gemini 3.8 Flash TTS / Charon sample style. The other 240 audio
streams are retained. Technical content, quizzes, PDFs, progress and entitlements
are untouched. No new agents or Lovable code generation.

Animation uses the approved shared AI theme and cabinet geometry. Other authored
concept diagrams build their component shapes, trace relationships and reveal
arithmetic results; door/drawer motion uses the depicted pivot/extension.
Original-heading transitions recover the existing non-Egyptian narration scene
boundaries. A mismatched scene count blocks the affected cell instead of using
approximate timing or regenerating its accepted audio.

Each cell retains the old mapping during render and encoding. A durable Actions
artifact contains a playable backup of the old stream, the replacement, props and
hash receipt before the mapping callback. The callback accepts only short-lived
GitHub OIDC identities from the exact owner/repository/branch/workflow/commit.
An expiring batch allowlist limits writes to the 320 captured lesson/locale cells.
Only video_guid changes, guarded by old GUID and unchanged content hash. Readback
and Bunny playback readiness are required. No service-role credential is copied
to GitHub. Unauthenticated, fork, main-branch and unreviewed-code calls are refused.

Each old video is deleted only after a second authenticated confirmation of the
playable replacement and its exact stored lesson mapping, and validation of the
old video's library/collection identity. Failure before that confirmation keeps
both videos. Backups have 90-day retention. Per-cell operational receipts
are evidence; the existing MD/XLSX remain the authoritative project registers.

The preparation workflow checks source coverage, motion renders and original audio
timings without paid TTS or media writes. The production workflow launches all
80 lesson jobs after its gates and proceeds per locale without waiting for the
entire batch. Failed/unknown TTS requests are reconciled, never blindly replayed.
