## المشكلة

داخل ملفات الدروس (`src/components/intro/lessons/`) لسه فيه جمل بتفترض إن المتعلم:

- جاي من درس سابق ("زي ما اتعلمنا في الدرس اللي فات…")
- ماشي في رحلة واحدة خطية ("في الموديول الجاي هنبدأ…")
- متفاعل مع المنصة كشخص واحد بيكمل كل المسارات

لكن الواقع الجديد: 5 مسارات مستقلة (Builder/Creator/Automator/Analyst/Business)، والمتعلم ممكن يدخل أي مسار لوحده، أو يقفز بين مسارات.

## السياسة المقترحة (default)

لو موافق نمشي عليها:

1. **داخل نفس المسار + نفس الموديول**: References مسموحة بس بشكل خفيف ("زي ما شفنا" بدون تحديد رقم درس).
2. **عبر المسارات**: ممنوع تماماً أي إشارة لمسار تاني (مثلاً درس Creator يقول "زي ما اتعلمنا في Builder").
3. **افتراضات الترتيب**: نشيل جمل زي "في الموديول الجاي"، "بعد ما خلصنا الـ Phase اللي فات"، "أول درس ليك في المنصة".
4. **ضمير "احنا/رحلتنا"**: نحوّله لمخاطبة مباشرة ("إنت/هتعمل") أو نشيله خالص.
5. **References لـ Lovable كأداة، أو لمفاهيم عامة (Frontend/Backend)**: تفضل زي ما هي.

## خطة التنفيذ

### Phase 1 — Audit أوتوماتيك (سريع، صفر تكلفة AI)

سكريبت `scripts/cross-path-audit.ts` يمشي على كل ملفات `src/components/intro/lessons/*.ts` ويطلع report فيه:

- الملف + رقم السطر + الجملة المشكوك فيها
- التصنيف: `prior-lesson-ref` / `next-lesson-ref` / `single-journey` / `cross-path` / `we-language`

Patterns هيتم البحث عنها:

- "اللي فات"، "السابق"، "الدرس اللي قبل"، "الموديول اللي فات"
- "الجاي"، "هنكمل في"، "في الموديول الجاي"، "بعد كده هنشوف"
- "Phase 1/2/3"، "المرحلة اللي فاتت"
- "احنا اتعلمنا"، "رحلتنا"، "بنينا مع بعض"
- أسماء مسارات تانية داخل ملف مش بتاعها (Builder mention in Creator file, etc.)

Output: `public/lesson-audit/cross-path-issues.json` + ملخص Markdown.

### Phase 2 — مراجعة + اعتماد

نعرض عليك الـ report (عدد المشاكل لكل مسار، أمثلة من كل تصنيف). إنت توافق على:

- السياسة (فوق)
- أي استثناءات
- البدء في الإصلاح

### Phase 3 — إصلاح بـ Agent درس درس

لكل ملف فيه issues:

- `spawn_agent` يقرا الدرس كامل + الـ issues + السياسة
- يرجّع نسخة معدّلة بتحافظ على المحتوى التعليمي وبس تشيل/تعيد صياغة الجمل المشكلة
- نطبّق التعديل + نضيف entry في `roadmap_items`
- نعمل rename لو الـ ID لسه قديم (حسب الـ memory rule)
- نشغّل `lesson-video.yml` لإعادة render الفيديو

التنفيذ batched: مسار واحد كل مرة، تبدأ بـ Builder (الأكبر) لو موافق.

### Phase 4 — Guardrail

نضيف الـ patterns كـ lint check في `scripts/jargon-lint.mjs` عشان أي درس جديد ميرجعش يكتب لغة بتفترض ترتيب.

## ملاحظات تقنية

- بناءً على memory: `gemini` only، batching للـ AI calls، roadmap logging إجباري بعد كل تعديل.
- إعادة render الفيديو إجبارية لأي درس بيتعدّل (مش typo).
- IDs ممكن يحتاجوا rename لو الدرس بيتعدّل وما اتسماش بالـ convention الجديد.

## القرارات المطلوبة منك قبل ما أبدأ

1. السياسة فوق ماشية؟ أو عايز تعديل؟
2. أبدأ بمسار معيّن (مثلاً Builder)، ولا أعمل Phase 1 (الـ audit) على الـ 5 مرة واحدة الأول؟
3. إعادة render الفيديوهات بعد كل تعديل: تمام، ولا عايز نأجلها لحد ما الإصلاح يخلص على المسار كله؟
